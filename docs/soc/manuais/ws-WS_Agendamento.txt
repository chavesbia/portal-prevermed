1.

Introdução

1.1

Objetivo
Possibilitar que o cliente realize a inclusão, alteração e exclusão de agendamentos, a partir do
consumo de WebService.

1.2

Funcionamento
1. As propriedades a serem enviadas para o SOC são populadas no WebService com os dados
do agendamento que será manipulado pelo cliente a partir de sua origem.
2. Após o serviço ser consumido, o SOC emite uma mensagem de retorno informando o
sucesso da operação, bem como possíveis irregularidades nos dados enviados.

1.3

Considerações
1. O desenvolvimento da lógica para a chamada ao WebService é de responsabilidade do
cliente;
2. O WebService foi projetado para incluir ou excluir um agendamento por vez que é
invocado;
3. O arquivo WSDL a ser usado está disponível nas configurações de integração do usuário.
4. O acesso ao serviço deve constar nas configurações de integração do usuário.
5. O usuário informado no campo “codigoUsuario” da TAG de identificação deve ser um
usuário diferente do usuário super SOC e ter os acessos necessários descritos no cadastro
do Serviço, no campo Observações.

2.

Parâmetros de Segurança para Acesso Ao Serviço

Para melhorar a segurança dos WebServices, A AGE Desenvolvimento LTDA, adota as políticas de
segurança fornecidas pela especificação WS-Security, utilizando a TAG Header com itens de
segurança conforme política. Segue um modelo do que deverá ser informado.
2.1

Configuração Padrão
A configuração padrão diz respeito ao uso de autenticação, que é um requisito obrigatório.

<wsse:Security xmlns:wsse="http://docs.oasis-open.org/wss/2004/01/oasis-200401-wsswssecurity-secext-1.0.xsd" xmlns:wsu="http://docs.oasis-open.org/wss/2004/01/oasis-200401wss-wssecurity-utility-1.0.xsd">

Timestamp

É o tempo de validade da requisição. Recomendamos o uso de um minuto.
Requisições com timestamp superior a dois minutos serão negadas.

Username

Código do usuário no sistema SOC precedido obrigatoriamente pela letra U
(disponível nas configurações de integração).

Password

Chave de acesso do usuário (disponível nas configurações de integração). Contudo
o cliente deverá informar o mesmo com o Tipo “PasswordDigest”.

Nonce

É um valor randômico que o cliente do serviço deverá criar para cada requisição
que enviar.

Signature

Tag responsável pela integridade dos dados trafegados em uma requisição.

EncryptedKey

Tag responsável por manter os dados seguros enquanto são trafegados.
