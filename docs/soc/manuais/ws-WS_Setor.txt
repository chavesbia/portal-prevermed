Especificação Técnica
1.

Introdução

1.1

Objetivo
Permitir ao cliente a possibilidade de criar, alterar, consultar e excluir setores, a partir do
consumo de WebService.

1.2

Funcionamento
1. As propriedades a serem enviadas para o SOC são populadas no WebService com os
dados do setor que será manipulado pelo cliente a partir de sua origem.
2. Após o serviço ser consumido, o SOC emite uma mensagem de retorno informando os
dados do setor manipulado, bem como possíveis irregularidades nos dados enviados.

1.3

Considerações
1. O desenvolvimento da lógica para a chamada ao WebService é de responsabilidade do
cliente;
2. O WebService foi projetado para atualizar/incluir/excluir um setor por vez que é
invocado, exceto a porta de consulta, que devolve uma lista de setores;
3. O arquivo WSDL a ser usado será enviado com as configurações de acordo com o
ambiente que for definido com o cliente.
4. O acesso ao serviço deve constar nas configurações de integração do usuário.
5. O certificado de conexão HTTPS disponibilizado no WebService é renovado anualmente,
de forma automática e antecipadamente à data de expiração.
6. O Webservice não oferece suporte ao paralelismo de requisições. As requisições devem
ser enviadas de forma sequencial. Em caso de identificação de paralelismo que
prejudique a performance do SOC, a integração será desligada sem aviso prévio.

2.

Parâmetros de Segurança para Acesso Ao Serviço
Para melhorar a segurança dos WebServices, A AGE Desenvolvimento LTDA, começou a adotar
as políticas de segurança fornecidas pela especificação WS-Security. Utilizando a TAG Header
com itens de segurança conforme política, segue um modelo do que deverá ser informado.

<wsu:Timestamp wsu:Id="TS-32E6B34377D7E4A58614607283662392">
<wsu:Created>xxxx</wsu:Created>
<wsu:Expires>xxxxx</wsu:Expires>
</wsu:Timestamp>
<wsse:UsernameToken wsu:Id="UsernameToken32E6B34377D7E4A58614607283662221">
<wsse:Username>xxxx</wsse:Username>
<wsse:Password Type="http://docs.oasis-open.org/wss/2004/01/oasis200401-wss-username-token-profile-1.0#PasswordDigest">xxxxx</wsse:Password>
<wsse:Nonce EncodingType="http://docs.oasisopen.org/wss/2004/01/oasis-200401-wss-soap-message-security1.0#Base64Binary">xxxxxxx</wsse:Nonce>

Username

Código do usuário no sistema SOC precedido obrigatoriamente pela

Password

Chave de acesso do usuário (disponível nas configurações de

Nonce

É um valor randômico que o cliente do serviço deverá criar para
cada requisição que enviar.

Signature

Tag responsável pela integridade dos dados trafegados em uma
requisição.

EncryptedKey

Tag responsável por manter os dados seguros enquanto são
trafegados.

2.2

Configurações adicionais para a tag wsse security
Para melhorar ainda mais a segurança dos WebServices, A AGE Desenvolvimento LTDA,

disponibiliza a opção de criptografia e assinatura digital nos WebServices. Quando utilizado a url da
versão com segurança deverá ser adicionado as tags Signature e EncryptedKey no header da requisição.
A AGE fornecerá um keystore contendo dois alias. Para a assinatura digital (Signature) utilizar o
alias clientkey e para a criptografia (EncryptedKey) utilizar o alias serverkey.
O web service com segurança adicional é utilizado em uma URL diferente da convencional. O
endereço consta no WSDL do serviço.

falhas:


Identificação Inválida: Mensagem retornada quando os dados informados na tag
identificacaoWsVo não configuram uma credencial válida de acesso aos Web Services.



Empresa Inválida: Mensagem retornada quando a empresa informada na propriedade
codigoEmpresa não é válida.



Usuário Sem Acesso: Mensagem retornada quando o usuário informado na
propriedade codigoUsuario não possui acesso para realizar a ação solicitada. Os acessos
necessários estão descritos no cadastro do serviço, nas configurações de integração da
empresa.



Login não Localizado: Mensagem retornada quando não é possível localizar o usuário
informado na propriedade codigoUsuario.



O campo SetorWsVo.codigoEmpresa não pode ser vazio!: Mensagem retornada
quando o campo codigoEmpresa é enviado vazio. Esse campo é obrigatório.

5.3

Falhas nas ações Inserir/Alterar
Ao inserir/alterar um setor, caso os dados não estejam de acordo, poderão ocorrer as seguintes
falhas:


Existe um setor com o nome informado: Mensagem retornada quando está se
tentando gravar (incluir ou alterar) o cadastro de um setor com o mesmo nome de um
setor já existente na empresa informada.



Existe um setor com o código RH informado: Mensagem retornada quando está se
tentando gravar (incluir ou alterar) o cadastro de um setor com o mesmo Código RH de
um setor já existente na empresa informada.



Código do setor inválido: Mensagem retornada quando o valor informado na
propriedade código não é um código válido de setor.
