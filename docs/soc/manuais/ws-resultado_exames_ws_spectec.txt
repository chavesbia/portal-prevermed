1.

Introdução

1.1

Objetivo
Permitir ao cliente incluir e alterar Resultados de Exames, facilitando o processo de comunicação
entre sistemas do cliente e o Sistema SOC. Além disso, também permite a exclusão de exames
de pedidos de exames existentes.

1.2

Funcionamento
1. As propriedades a serem enviadas para o SOC são populadas no WebService com os
dados do resultado que será manipulado pelo cliente a partir de sua origem;
2. Após o serviço ser consumido, o SOC emite uma mensagem de retorno informando os
dados do resultado manipulado, bem como possíveis irregularidades nos dados enviados.

1.3

Considerações
1. O desenvolvimento da lógica para a chamada ao WebService é de responsabilidade do
cliente;
2. O cliente poderá utilizar a ferramenta “Exporta Dados”, pela qual será possível obter os
códigos sequenciais da “Ficha” (Pedido de Exame) e do Resultado, necessários para a
manipulação dos mesmos;
3. O acesso ao serviço deve constar nas configurações de integração do usuário;
4. O certificado de conexão HTTPS disponibilizado no WebService é renovado anualmente,
de forma automática e antecipadamente à data de expiração.
5. O Webservice não oferece suporte ao paralelismo de requisições. As requisições devem
ser enviadas de forma sequencial. Em caso de identificação de paralelismo que
prejudique a performance do SOC, a integração será desligada sem aviso prévio.

2.3

Considerações para as Propriedades da tag wsse security
Propriedade

Timestamp

Detalhes
O valor inserido na tag define o tempo de vida do timestamp e,
consequentemente, da mensagem. Mensagens enviadas com timestamp
expirado devem ser rejeitadas pelo Web Service que as estão consumindo.

Username

Código do usuário no sistema SOC precedido obrigatoriamente pela letra U
(disponível nas configurações de integração).

Password

Chave de acesso do usuário (disponível nas configurações de integração).
Contudo o cliente deverá informar o mesmo com o Tipo “PasswordDigest”.

Nonce

É um valor randômico que o cliente do serviço deverá criar para cada
requisição que enviar.

Signature

Tag responsável pela integridade dos dados trafegados em uma requisição.

EncryptedKey

Tag responsável por manter os dados seguros enquanto são trafegados.

2.4

Configurações adicionais para a tag wsse security
Para melhorar ainda mais a segurança dos WebServices, A AGE Desenvolvimento LTDA,

disponibiliza a opção de criptografia e assinatura digital nos WebServices. Quando utilizado a url da
versão com segurança deverá ser adicionado as tags Signature e EncryptedKey no header da requisição.
A AGE fornecerá um keystore contendo dois alias. Para a assinatura digital (Signature) utilizar o
alias clientkey e para a criptografia (EncryptedKey) utilizar o alias serverkey.
O webservice com segurança adicional é utilizado em uma URL diferente da convencional. O
endereço consta no WSDL do serviço.

A falha acima ocorre quando o elemento de segurança “timestamp” é violado. O timestamp
verifica a validade da mensagem enviada em termos de tempo.
O sender especifica o tempo de validade, então, dois elementos são definidos no momento em
que a mensagem é enviada:
Onde:

<wsu:Created>2014-06-18T20:20:44.623Z</wsu:Created>

wsu:Created = hora atual;

<wsu:Expires>2014-06-18T20:21:44.623Z</wsu:Expires>

wsu:Expires = wsu:Created + (tempo de validade);

Verificar item 2 desse documento
de especificação.

•

Ajustar horário do computador;
