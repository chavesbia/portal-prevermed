150. SOC Integrador

1. Configurando a tela do Usuário Integrador
Atualizado em 03/06/2025

Vídeo
Para atender às demandas de integração, foi desenvolvida uma interface que centraliza
todos os Web Services disponíveis no SOC. Nela, os usuários poderão selecionar os
serviços desejados de forma intuitiva. Com essa ferramenta, o usuário ganha mais
autonomia para realizar integrações com outros sistemas conforme suas necessidades.
As funcionalidades oferecidas pelos Web Services devem ser entendidas como uma
"extensão" das telas do SOC. Isso significa que todas as regras aplicadas em tela e
devem ser igualmente respeitadas nas ações realizadas via Web Service.
A autenticação para integração será realizada por meio de um identificador único para
cada usuário do tipo Web Service, permitindo definir quais empresas cada usuário pode
acessar.
IMPORTANTE:
- Para que o usuário visualize a ferramenta, é necessário ter acesso ao programa
"Configuração de Integração".
- Os Web Services disponibilizados na tela "Configuração de Integração" NÃO geram
custos do lado do SOC.
- As configurações a seguir não serão possíveis em um acesso SOCNET.

algumas configurações de acesso. Para isso, realize os seguintes passos:

ao sistema.

O que são Web Services?

Web Service é uma solução utilizada na integração de sistemas e na comunicação entre
aplicações diferentes. Com esta tecnologia é possível que novas aplicações possam
interagir com aquelas que já existem e que sistemas desenvolvidos em plataformas
diferentes sejam compatíveis. Os Web Services são componentes que permitem às
aplicações enviar e receber dados em formato XML.

Funcionamento
As propriedades a serem enviadas para o SOC são populadas no Web Service com os
dados da empresa que será manipulado pelo cliente a partir de sua origem. Após o
serviço ser consumido, o SOC emite uma mensagem de retorno informando os dados da
empresa, bem como possíveis irregularidades nos dados enviados.

Considerações
- O desenvolvimento da lógica para a chamada ao Web Service é de responsabilidade do
cliente.
- O arquivo WSDL a ser usado está disponível nas configurações de integração da
empresa (Menu > Cadastro > Estrutura > Empresa/Cliente - Configuração de Integração)
- O acesso ao serviço deve constar nas configurações de integração da empresa.
- A chave de acesso da empresa principal permite acesso a todas as empresas.
- A chave de acesso de uma empresa cliente só permite acesso à mesma.
- O usuário informado no campo codigoUsuario da Tag de identificação deve ser um
usuário diferente do usuário informado no campo codigoResponsavel e ter os acessos
necessários descritos no cadastro do serviço, no campo Observações.
IMPORTANTE: É responsabilidade do usuário a configuração e implementação de Web
Service em sua base de dados.
Para melhorar a segurança dos Web Services, a AGE Desenvolvimento LTDA, adota as
políticas de segurança fornecidas pela especificação WS-Security. Utilizando a TAG
Header com itens de segurança conforme política, segue um modelo do que deverá ser
informado.

Se "false": Desabilitará o campo Acesso Maestro/SOC Flow.
Se vazio: Nenhuma ação deve ser realizada.
Se a tag não for enviada: Nenhuma ação deve ser realizada.

ser retornado o erro "O campo empresaIdentificador é obrigatório quando o

CODIGO_SOC
CODIGO_CLIENTE

1 - Admissional
2 - Periódico

5 - Demissional
6 - Monitoração Pontual
10 - Consulta

12 - Acidente

recomendacoes: Se o valor ultrapassar 200 caracteres será retornado erro.

fichaBranco: Quantidade de vias de Fichas em Branco a serem geradas. Os valores

guiaExame: Quantidade de vias de Guias de Exame a serem geradas. Os valores

4. Integração com Sistemas Parceiros
Atualizado em 03/06/2025

Procedimento
A ferramenta Integrações com Sistemas Parceiros permite que sejam realizadas
integrações com Empresas Parceiras do SOC de maneira simples e rápida. A partir de
um Token, fornecido pela empresa parceira, com apenas um clique será possível
realizar a integração com, por exemplo, um Sistema de Folha.
IMPORTANTE: Antes de realizar as configurações de integração, deve ser realizado um
contrato com um dos parceiros para que as informações necessárias sejam
disponibilizadas.
Para isso, acesse a tela de Configuração de Integração, através do:
Menu > Cadastros > Estrutura > Empresa/Cliente
Localize e selecione a empresa que será integrada.
Clique no ícone

- Configuração de Integração.

Clique no ícone

- Integrar com Parceiros.

Para configurar a integração, clique em Ativar Integração.

Na aba Serviços Disponíveis, será possível visualizar os serviços atendidos pela
Empresa Parceira, por exemplo, Funcionários Modelo 2, Resultado de Exames, entre
outros.
Na Aba Sobre Este Acordo, está disponível o Termo de Uso da funcionalidade. A
integração só deve ser ativada mediante o aceite dos Termos de Uso.
O token de acesso fornecido pela empresa parceira deve ser preenchido abaixo do
aceite do Termo de Uso, para que a integração possa ser ativada. Uma vez aceito o
termo de acordo e preenchido o token fornecido pelo sistema parceiro, clique em Ativar
para ativar a integração.

Observação: É possível realizar a ativação da integração para mais de um tipo diferente
de Empresa Parceira.
Exemplo: É possível integrar o SOC com um sistema de folha e outro sistema de
treinamento.

Caso a Empresa Parceira tenha informado os Parâmetros de Segurança (Login, Senha e
Token), será necessário informá-los por meio do ícone
- Parâmetros de Segurança,
para que a integração possa ser efetiva.

Caso necessário, a integração pode ser desativada clicando em Desativar Integração,
ao lado da Empresa Parceira Integrada.
Observações e regras:
1. O ícone
- Integrar com Parceiros somente poderá ser acessado pelo Usuário ADM
da empresa.
2. A Integração com parceiros em empresas do tipo Prestador deve ser realizada a nível
de empresas cliente.
3. Caso já existam dados cadastrados no SOC, será necessário o saneamento dos
dados. Para eventuais dúvidas sobre o saneamento, acione o seu prestador de serviços.
Mais detalhes sobre o saneamento dos dados também podem ser consultados no
manual Saneamento de Base para Integrações.
4. Quando ativada a integração, uma vez que um dado seja integrado, qualquer
alteração deste dado deve ser realizada no sistema de origem. Desta forma, a
integração realizará a atualização do dado no sistema de destino.
5. Em caso de dúvidas na ativação da integração no SOC, realize abertura de chamado
no Suporte SOC.
6. Somente será possível ativar a integração com a Sênior, caso a empresa não possua
o parâmetro Inativa funcionário na emissão do ASO demissional, localizado em
Parâmetros Gerais, habilitado.
7. Empresas Parceiras do SOCnão possuem acesso ao ícone Certificado Digital, da tela
780 - Configurações Pessoais.

Web Services e Exporta Dados
O SOC disponibiliza, de forma gratuita, todos os Web Services (WSs) e rotinas de Exporta
Dados documentados oficialmente. Esses recursos permitem que sua empresa
desenvolva integrações personalizadas, conforme as necessidades específicas da
operação.
A documentação oficial pode ser consultada em nossa Central de Ajuda (Download) para
obter detalhes técnicos sobre endpoints, formatos de dados e autenticação.

Log de Integração
A criação, ativação e manutenção do log de integração (incluindo registros de
requisições, respostas e erros) é de responsabilidade do sistema que estiver integrando
com o SOC, conforme as boas práticas de desenvolvimento.
Atenção: O SOC não mantém logs contínuos de terceiros. Nossa infraestrutura registra
apenas eventos críticos, com foco no monitoramento interno de disponibilidade e
estabilidade.

Investigação de Incidentes
Em situações específicas, como falhas ou comportamentos inesperados que exijam
análise detalhada, o SOC poderá ativar temporariamente um log interno.
Essa ativação é exclusiva para fins de diagnóstico.
Não se trata de um serviço contínuo ou permanente de logging.

Customizações
Caso sua empresa necessite de:
Log de Integração permanente hospedado no SOC, ou
Customizações específicas nos Web Services ou nas rotinas de Exporta Dados,
será necessário solicitar um projeto customizado.
Para iniciar essa solicitação:
1. Especifique o escopo técnico desejado (ex: endpoints envolvidos, dados a registrar).
2. Informe a expectativa de volume de requisições e prazos.
3. Abra um PSE direcionado à Equipe de Projetos do SOC, para que a demanda seja
avaliada e uma proposta comercial seja apresentada.

181. Integrações com Parceiros

1. Saneamento de Base para Integrações

Atualizado em 17/06/2025

Este manual descreve o procedimento a ser seguido quando o cliente deseja integrar
seu sistema com uma solução externa, mas existem divergências nos dados cadastrais
entre os dois sistemas como, por exemplo, diferenças nos códigos e nomes de
hierarquias, funcionários, entre outros elementos.
O propósito deste método é oferecer uma forma segura e sem custos adicionais para
realizar o saneamento da base de dados. Após essa etapa, será possível viabilizar a
integração entre os sistemas de maneira consistente e eficaz.
A solução consiste em inativar a empresa cliente atualmente cadastrada e criar uma
nova, com os dados devidamente alinhados ao sistema externo com o qual se deseja
integrar. Dessa forma, garante-se a compatibilidade necessária para o correto
funcionamento da comunicação entre os sistemas.
.

IMPORTANTE: Antes de optar pela execução deste processo, é fundamental considerar os ponto
.

Pontos de Atenção
1. Validação de Cadastros Específicos
Será necessário revisar os cadastros de exames e riscos para verificar se existem
registros criados exclusivamente para a empresa cliente atual. Caso isso ocorra, esses
cadastros deverão ser copiados manualmente para a nova empresa.
2. Limitações do Procedimento
Este procedimento não inclui a migração dos seguintes dados:
SOCGED;
Respostas de personalização;
Valorizações;
Portal do Prestador;
Entrega de EPI;
CIPA;
Treinamentos;
Afastamentos;
CAT;
Atividades.
Portanto, após a execução, todas as informações relacionadas a esses itens deverão ser
consultadas, se necessário, na empresa original (que será inativada).
3. Preservação dos Dados
Nenhuma informação será excluída da base de dados durante este processo. Todos os
dados permanecerão disponíveis para consulta na Empresa original.

4. Alternativa via Customização
Caso este procedimento não atenda às necessidades do cliente, é possível solicitar um
processo de saneamento de base por meio de Customização. Essa alternativa está
sujeita a análise técnica, definição de prazos e custos de desenvolvimento. Para mais
detalhes, consulte os manuais Orçamento para Customização e PSE - Projeto Sob
Encomenda.
Etapas para Realização do Saneamento de Base
Para executar o procedimento de saneamento de base, siga as etapas abaixo:
1. Inativar a Empresa Cliente
A primeira etapa consiste em inativar a empresa cliente atual.
Para isso, acesse o cadastro da Empresa e desmarque o parâmetro Ativo.
Essa ação garante que a empresa não seja mais utilizada em processos futuros,
preservando seus dados apenas para consulta.

Para mais detalhes sobre inativação de empresa, acesse o manual Inativar Empresas.
2. Criar uma Nova Empresa Cliente
Após inativar a empresa anterior, crie uma nova empresa cliente que a represente.

os dados devidamente ajustados. Utilize a empresa anterior como referência para
replicar as configurações necessárias.

3. Tag de Segurança (wsse:Security)

1. Como realizar a geração dos Hash's de Password Digest e Nonce na requisição?
R: O Nonce é um valor randômico que deve ser gerado em base 64 e deve ser
renovado a cada requisição enviada.
A criptografia da Password Digest deve ser feita de acordo com a lógica do padrão WSSecurity, onde PasswordDigest = Base 64 (SHA-1(Nonce+Created+Password)).
Erro relacionado: The security token could not be authenticated or authorized
2. Estou enviando os dados de Timestamp com o horário correto. Por que está sendo
retornado o erro "The message has expired"?
R: O horário da máquina que faz o envio da requisição deve estar sincronizado com o
horário oficial. As propriedades são do tipo dateTime Xml e o horário expresso deve
estar em acordo com o formato dateTime enviado. Exemplo: Se enviado no formato
UTC-0 (Indicado pela letra "Z" ao final do conteúdo da propriedade), o horário deve ser
expresso sincronizado com o padrão UTC-0. É recomendado que o tempo de validade
da requisição informado seja de 60 segundos. Requisições com Timestamp superior a
dois minutos serão negadas.
Erro relacionado: The message has expired
3. Por que estou recebendo o retorno "An error was discovered processing the wsse:
security header"?
R: Este erro é retornado quando existe alguma falha no header de segurança informado
na requisição. O header deve ser gerado de acordo com o padrão WS-Security. Mais
detalhes podem ser consultados na seção "Parâmetros de Segurança para Acesso Ao
Serviço" da documentação técnica do serviço desenvolvido.
4. Por que estou recebendo o retorno "MustUnderstand headers: [{http://docs.oasisopen.org/wss/2004/01/oasis-200401-wss-wssecurity-secext-1.0.xsd}Security] are not
understood."?
R: Este erro é retornado quando é informado o header de segurança para um Web

6. O que é o Nonce?

R: O nonce é um componente essencial no padrão de segurança WS-Security utilizado
para prevenir ataques de repetição (replay attacks). A palavra "nonce" decorre da
expressão "number used once" (número usado uma vez).
7. Estou recebendo o erro "A replay attack has been detected". O que ele significa?
R: O erro "A replay attack has been detected" no padrão de autenticação WS-Security
indica que uma tentativa de ataque de repetição foi detectada. Essa mensagem é
gerada quando o valor enviado na tag "Nonce" já foi enviado em uma requisição
anterior.
Processo de Uso do Nonce
1. Geração: Quando uma mensagem é criada, um nonce é gerado aleatoriamente.
2. Inclusão na Mensagem: O nonce é incluído no cabeçalho de segurança da mensagem
SOAP, junto com outras informações de segurança como o timestamp e o password
digest.
3. Verificação pelo Receptor: O receptor da mensagem verifica se o nonce já foi usado
anteriormente. Se o nonce já foi recebido (indicando uma possível tentativa de
repetição), a mensagem é rejeitada.
8. Qual a função do Nonce?
R: 1. Valor Único: O nonce é um valor aleatório e único que é gerado para cada
mensagem enviada. Isso garante que cada mensagem tem um identificador exclusivo.
2. Prevenção de Ataques de Repetição: Ao incluir um nonce em uma mensagem, junto
com um timestamp (marca de tempo), o sistema pode verificar se a mensagem é
válida e única. Isso impede que uma mensagem capturada por um atacante seja
retransmitida de maneira fraudulenta.
3. Parte do Password Digest: Em muitos casos, o nonce é combinado com outros
elementos, como um timestamp e uma senha, para criar um password digest seguro.
Este digest é incluído na mensagem e permite que o receptor verifique a autenticidade
e integridade da mensagem.

13. Autenticação Web Service Security (WSS)
Atualizado em 23/10/2025

A autenticação é o primeiro passo para utilizar o Webservice SOAP. Funciona como um
login, onde um usuário e senha desejam acessar o sistema, mas é realizada dentro de
um envelope XML SOAP, utilizando uma tag chamada header. Esta tag deve ser
preenchida conforme as definições do padrão Web Service Security (WSS), que requer os
elementos UsernameToken e Timestamp.
Uma característica importante é que a senha deve ser informada em um formato
específico do padrão WSS:
Password Digest
Isso significa que a senha enviada na requisição precisa ser criptografada de acordo com
as definições desse padrão.

Para construir corretamente sua tag header com UsernameToken, Password Digest e
Timestamp (no padrão UTC) para autenticar uma requisição no Web Service que utiliza
WSS, siga os passos abaixo:

Passos para Construção
Gerar o Nonce: Um valor único e aleatório em base64.
2. Gerar o Timestamp: O Timestamp deve sempre estar no formato UTC e é composto
por duas tags:
wsu:Created: Carimbo de data e hora que representa o instante atual em
formato UTC.
wsu:Expires: Este valor é igual ao wsu:Created mais 60 segundos.
3. Concatenar Nonce, Created e Senha: Para criar o Password Digest.
4. Aplicar SHA-1 e Codificar em Base64: Para obter o Password Digest.
5. Montar o Header XML: Incluindo todas as informações geradas.
1.

Exemplo de Header XML

Descrição das Tags
wsu:Timestamp: Define o período de validade da mensagem.
wsu:Created: Indica quando a mensagem foi criada.
wsu:Expires: Indica quando a mensagem expira.
wsse:UsernameToken: Contém as credenciais de autenticação.
wsse:Username: O nome de usuário.
wsse:Password: A senha em formato digest. O atributo Type especifica que a
senha está em formato digest.
wsse:Nonce: Um valor único e aleatório usado para evitar ataques de repetição.
wsu:Created: O timestamp indicando quando o token foi criado.

Documentação oficial WSS disponível em: http://docs.oasis-open.org/wss/v1.1/wss-v1.1spec-os-UsernameTokenProfile.pdf

Gerenciamento de acessos
Manter controle rigoroso dos usuários com permissão para utilizar o Exporta Dados, evitando acessos
indevidos e/ou a criação de exportações não autorizadas.
Autenticação em integrações SOAP

Chave de acesso por cliente

Rotação periódica da chave de acesso

Ao compartilhar a string de teste (JSON com os parâmetros de entrada) em chamados de suporte ou no
corpo de e-mails, omitir parcialmente o valor do parâmetro chave.
Proteção de informações em evidências visuais
Em prints de tela que demonstrem a chamada do Exporta Dados, cobrir parcialmente o valor do parâmetro
chave antes de qualquer compartilhamento.
Compartilhamento seguro da chave completa
Quando for necessário compartilhar a string de teste contendo o valor completo do parâmetro chave, fazêlo exclusivamente por meio de um arquivo de texto compactado (ZIP) protegido por senha, sendo a senha
enviada separadamente e de forma individual apenas às pessoas autorizadas.

156. Processamento Assíncrono

1. Processamento Assíncrono

Atualizado em 06/06/2025

A funcionalidade Processamento Assíncrono permite a extração de dados de
processamentos complexos por meio de agendamento. Realizado o processamento, os
dados são disponibilizados para consulta em seu respectivo Exporta Dados.
Solicitação de Processamento
A solicitação de processamento deve ocorrer por meio do Web Service Solicitação de
Processamento Assíncrono, pelo qual será informado o tipo de processamento
desejado, bem como os parâmetros que devem ser utilizados na execução.
Uma vez realizada a solicitação de processamento, será retornado o código. A execução
será realizada a partir da 01h00 do dia subsequente. Os dados serão processados e
armazenados, podendo ser consultados por meio do Exporta Dados correspondente ao
tipo solicitado, por meio do código da solicitação retornado.
Portanto, o fluxo da solução consiste em dois momentos: primeiramente, a solicitação

121. #SI - Segurança da Informação

1. Política de Segurança da Informação e Privacidade

1. OBJETIVO
Definir as diretrizes de segurança da informação e privacidade da AGE Desenvolvimento
de Sistemas.

2. ABRANGÊNCIA

Todas as unidades de negócios, colaboradores, prestadores de serviços, parceiros e
fornecedores da AGE Desenvolvimento de Sistemas.

3. RESPONSÁVEL
A Alta direção da AGE Desenvolvimento de Sistemas é responsável pela viabilização das
condições necessárias para a devida aplicabilidade desta Política e a Coordenadoria de
Segurança da Informação é responsável pela atualização dessa Política e Normas.

4. TERMOS E DEFINIÇÕES
Vide Manual de Organização de Conceitos.

5. DIVULGAÇÃO E DECLARAÇÃO DE RESPONSABILIDADE
A Política deve ser de conhecimento de todos. Sua divulgação e educação são de suma
importância para a empresa, e poderá ser divulgada ou publicada das seguintes formas:
a) Impressa;
b) Digital; e
c) Sonora ou Áudio visual.
Cabe as unidades de negócios juntamente com a equipe de segurança da informação e
equipe de marketing e divulgação analisar e definir a melhor forma de divulgação,
considerando e respeitando a cultura e costumes, leis e regulamentos vigentes e
evitando qualquer tipo de discriminação.
Todos os colaboradores, prestadores de serviços, parceiros e fornecedores que tenha
acesso a informações, devem aderir formalmente ao "Termo de Ciência e Recebimento
da PSI", comprometendo-se a respeitar esta Política e suas normas de forma integral.

6. PRINCÍPIOS
PRIVACIDADE

DA

POLÍTICA

DE

SEGURANÇA

DA

INFORMAÇÃO

E

Entende-se por informação todo e qualquer conteúdo ou dado que tenha valor para
organização ou seus clientes. Ela pode estar guardada para uso restrito ou exposta ao
cliente para consulta ou manuseio.
Entende-se por privacidade o direito da inviolabilidade à intimidade, à vida privada, à
honra e a imagem das pessoas.
Todo tipo de ativo de informação é classificado, podendo ser rotulado como:
Confidencial, Privado, Sensível ou Público. Independente da forma apresentada ou o
meio do qual a informação é compartilhada ou armazenada, a informação é o maior
ativo da AGE Desenvolvimento de Sistemas e de seus clientes, e por isso essencial ao
negócio, por esses motivos deverá ser devidamente protegida e utilizada de modo ético
e seguro.
Para tanto definimos os pilares de Segurança da informação:
a) Confidencialidade: Garantir que a informação não seja revelada ou esteja disponível
para indivíduos, entidades e processos não autorizados;
b) Integridade: Garantir a salvaguarda da exatidão e totalidade da informação e dos
métodos de processamento.

c) Disponibilidade: Garantir que a informação esteja sempre acessível e disponível
quando necessário. Considerando a:
Prontidão: Ser acessível sempre que necessária,
2. Continuidade: Manter-se disponível mesmo quando houver falhas nos sistemas,
3. Robustez: Atender a todos os usuários do sistema sem que haja uma degradação
que comprometa o resultado.
1.

d) Autenticidade: Garantir que a autoria seja confirmada.

7. OBJETIVOS DE SEGURANÇA DA INFORMAÇÃO
O Sistema de Gestão de Segurança da Informação e Privacidade (SGSIP) visa preservar
a Confidencialidade Integridade, Disponibilidade e Autenticidade das informações da
AGE. Deve estar integrado com os processos da empresa e suas estruturas
administrativas. Os objetivos da segurança da informação estão disponíveis no
documento P-SGSI-052 Objetivos Estratégicos da Segurança da Informação.

8. DIRETRIZES DA SEGURANÇA DA INFORMAÇÃO
Para endereçar todo o esforço e manutenção necessária para a Segurança da
Informação, a AGE Desenvolvimento de Sistemas estabelece as seguintes diretrizes:
a) Uma estrutura de Gestão da Segurança da Informação e Privacidade foi estabelecida
e mantida com apoio da alta direção, através de um Sistema de Gestão de Segurança
da Informação e Privacidade (SGSIP);
b) A informação deverá ser utilizada com senso de responsabilidade e de modo ético e
seguro por todos, em benefício exclusivo dos negócios corporativos;
c) A AGE Desenvolvimento de Sistemas reserva-se o direito de monitorar e registrar
todo o uso das informações geradas, armazenadas ou veiculadas na empresa. Para
tanto foram criados e implantados controles apropriados e trilhas de auditoria ou
registros de atividades em todos os pontos e sistemas que a empresa julgou necessário
para reduzir os riscos;
d) Todos os ativos de informação estão devidamente identificados, classificados e
monitorados;
e) A identificação de cada usuário da AGE Desenvolvimento de Sistemas é única,
pessoal e intransferível, qualificando-o como responsável pelas ações realizadas;
f) Todos os riscos deverão ser analisados, classificados e apresentados a um Comitê
que deliberará sobre o Tratamento adequado para tais;
g) Todos os incidentes de segurança devem ser reportados para a área de Segurança
da Informação para que sejam analisados, avaliados e tratados pela área responsável.
h) A AGE Desenvolvimento de Sistemas identifica, segue, documenta e mantem
atualizadas as leis que regulamentam suas atividades, bem como dos aspectos de
propriedade intelectual.
i) A AGE Desenvolvimento de Sistemas, através de sua alta direção definiu os Objetivos
Estratégicos de Segurança da Informação considerando esta Política, os requisitos de
Segurança da Informação aplicáveis e os resultados da Gestão de Riscos.

9. GESTÃO DE SEGURANÇA DA INFORMAÇÃO E PRIVACIDADE
Para manter um nível satisfatório de segurança constitui-se o Comitê de Gestão de
Segurança da Informação e Privacidade (CGSIP) que adotará as seguintes normas, e
outras que possam ser criadas, para sustentar as diretrizes apresentadas:
a) Norma de Controle de Acesso: O controle de acesso dos colaboradores internos ou
externos aos ativos de informação deve ser devidamente aprovado pelo responsável
pela informação (gestor, diretoria ou responsável conforme definido nos documentos da
informação), a qual o acesso permitirá a manipulação, quer seja para simples consulta
ou para alteração;
b) Norma de Correio Eletrônico: O uso do e-mail sob domínio@soc.com.br, será
permitido para colaboradores internos e externos, e para terceiros somente quando for
necessário, e por tempo determinado pela gerência da área solicitante mediante a
Termo de responsabilidade.
Este tempo poderá ser prorrogado mediante nova solicitação da gerência da área.
c) Norma de Cópias de Segurança da Informação (Backup): Cópias de segurança
(backup) através de mídias específicas de informações que são consideradas vitais para
o sistema e para a retomada das atividades da área em caso de contingência;
d) Norma de Desenvolvimento Seguro: Regras para o desenvolvimento seguro de
sistemas e softwares estão estabelecidas e aplicadas aos desenvolvimentos realizados
dentro da organização;
e) Norma de Classificação e Manuseio da Informação: As informações devem ser
classificadas e manuseadas de acordo com a confidencialidade e as proteções
necessárias, da seguinte forma: Pública, Sensível, Privada e Confidencial, e devem ser
tratadas, armazenadas e descartadas de maneira correta para garantir os aspectos de
segurança da informação e privacidade no negócio da AGE e nas informações dos seus
clientes;
f) Norma de Conduta Ética de Colaboradores: As responsabilidades de todos quanto a
segurança da informação, seguindo requisitos mínimos de conduta e ética estão
definidas;
g) Norma de Gestão de Ativos: Os ativos tangíveis e intangíveis de informação estão
identificados de forma individual, inventariados, protegidos e monitorados de acessos
indevidos. As mídias são gerenciadas de forma adequada, conforme os requisitos de
segurança da informação. O acesso remoto deve estar registrado e o seu tempo
definido.
h) Norma de Gerenciamento de Chaves Criptográficas e Transmissão de Informações:
Um conjunto de regras para garantir a padronização das técnicas criptográficas, a
aplicação adequada das mesmas e responsabilidades para manter a segurança no
transporte ou armazenamento das informações independente do meio utilizado. Quanto
à transmissão de informações, este recurso é utilizado para garantir a privacidade na
comunicação dos dados da AGE Desenvolvimento de Sistemas e de seus clientes;
i) Norma de Gerenciamento de Mudanças: Um processo de gestão de mudanças está
em vigor para garantir que controles e modificações nos sistemas ou recursos de
processamento da informação sejam realizados com planejamento, afim de não
ocasionar falhas operacionais ou de segurança no ambiente produtivo da organização;

j) Norma de Mesa Limpa e Tela Protegida: Para garantir a proteção das informações de
maneira eficaz e reduzir os riscos de acesso não autorizado, perda ou dano à
informação durante e fora do horário normal de trabalho, foram adotadas medidas de
segurança;
k) Norma de Análise, Avaliação e Tratamento de Riscos: Os riscos são identificados por
meio de um processo estabelecido para análise de vulnerabilidades, ameaças e
impactos sobre os processos nos aspectos de segurança da informação
(Confidencialidade, Integridade e Disponibilidade);
l) Norma de Gestão de Incidentes de Segurança da Informação: Todos os incidentes
que afetem a segurança da informação devem ser reportados a área de Segurança da
Informação através do canal seguranca@soc.com.br ou no Maestro BPM que analisará o
incidente e tomará as ações devidas, repassando a tratativa as áreas responsáveis;
m) Norma de Tecnologia da Informação e Uso aceitável de Ativos: Estão
regulamentadas as responsabilidades de Tecnologia da Informação e restrições do uso
de ativos na organização;
n) Norma de Indicadores e Métricas do SGSI: Para garantir a melhoria contínua do
Sistema de Gestão da Segurança da Informação e Privacidade (SGSIP), com base na
norma ISO/IEC 27001:2013, contém todos os indicadores e métricas para monitorar-se
o ciclo PDCA;
o) Norma de Conformidade: Define regras para garantir que não ocorram violações
jurídicas, regulamentares ou contratuais nos requisitos de segurança da informação na
organização;
p) Norma de Segurança Física e Ambiente: Garantir que o acesso físico às instalações
onde os ativos de TI e informações criticas à continuidade do negocio estejam
armazenados sejam controlados de forma a garantir a sua proteção, disponibilidade,
integridade e confidencialidade;
q) Norma de Fornecedores: Garantir que os contratos com fornecedores, parceiros e
terceiros, estejam sempre pautados em uma postura ética compatível com os
princípios, valores da AGE e promovam uma relação mais justa e sustentável;
Quando razões tecnológicas ou determinações superiores tornarem impossível a
aplicação dos requisitos previstos nesta política o responsável e/ou solicitante deverá
documentá-las imediatamente à área de Segurança da Informação ou área responsável
para que possibilite a adoção de medidas alternativas que minimizem os riscos, bem
como um plano de ação para corrigi-los, monitorá-los ou eliminá-los.

10. MONITORAMENTO E AUDITORIA
A AGE Desenvolvimento de Sistemas monitora e registra todo o uso das informações
geradas, armazenadas ou veiculadas na empresa. Para tanto a organização mantem
controles apropriados e trilhas de auditoria ou registros de atividades em todos os
pontos e sistemas que a empresa julgou necessário para reduzir os riscos, e reservarse o direito de:
a) Implantar outros sistemas de monitoramento de acesso às estações de trabalho,
servidores internos e externos, correio eletrônicos, navegação, Internet, dispositivos

móveis ou wireless e outros componentes da rede. A informação gerada por estes
sistemas de monitoramento poderá ser usada para identificar usuários e respectivos
acessos efetuados;
b) Inspecionar qualquer arquivo que esteja na rede, no disco local da estação ou
qualquer outro ambiente, visando assegurar o rígido cumprimento desta PSI;
c) Instalar outros sistemas de proteção e detecção de invasão para garantir a
segurança das informações e dos perímetros de acesso.

11. PENALIDADES
Para toda e qualquer infração à PSI e às Normas de Segurança da Informação deverá
ser aberto um incidentes de segurança da informação, tratado de acordo com a Norma
de Gestão de Incidentes de Segurança da Informação e, por conseguinte, apurada
através de procedimentos internos, que deve ser conduzido pelo gestor da área em que
se encontra alocado o profissional que cometeu a infração, em conjunto com a área de
Recursos Humanos.
Caso o CGSIP julgue cabível, o colaborador envolvido poderá, enquanto durar o
processo de apuração interna, ser afastado da função ou suspenso.
Ao colaborador suspeito de cometer violações à Política e Normas de Segurança da
Informação, deverá ser assegurado tratamento justo e correto, sendo que toda e
qualquer medida resultante de sua infração deverá ser aplicada com proporcionalidade
à ocorrência com base no Código de Conduta, Termo de Confidencialidade, Manual do
Colaborador e Processo Disciplinar da AGE Desenvolvimento de Sistemas e legislações
vigentes.
A AGE Desenvolvimento de Sistemas exonera-se de toda e qualquer responsabilidade
decorrente do uso indevido, negligente ou imprudente dos recursos e serviços
concedidos aos seus colaboradores, terceiros e parceiros, reservando-se o direito de
punir os infratores, analisar dados e evidências para obtenção de provas a serem
utilizadas nos processos investigatórios e adotar as medidas legais cabíveis.

1. Política de Privacidade
A AGE se empenha no cumprimento das leis de proteção de dados aplicáveis aos seus
negócios, incluindo-se, mas não se limitando, a Lei Geral de Proteção de Dados
Pessoais - LGPD. A AGE respeita sua privacidade on-line e a necessidade de proteção e
gestão de quaisquer informações de identificação pessoal ("Dados Pessoais") que você
venha a compartilhar conosco.

2. Dados Pessoais
Dados Pessoais referem-se a qualquer informação que permita a sua identificação total
ou parcial e que esteja relacionada a uma pessoa singular identificada ou identificável
(também conhecida como titular dos dados), tais como: nome, número de origem
documental, dados de localização, entre outros, os quais através de um identificador online, aliados a um ou mais fatores específicos, resultem na identidade dessa pessoa
natural.

3. Uso de Dados Pessoais
A AGE através das informações, exclusivamente inseridas pelos Clientes, coleta seus
Dados Pessoais para os seguintes fins:
para fornecer determinados serviços personalizados a você, com a permissão do
Cliente, ou à empresa a qual você está associado;
para apoiar atividades como atendimento ao cliente, marketing, desenvolvimento de
produtos e serviços de recrutamento e seleção;
para informar a você ou a empresa com quem você está associado dos nossos
produtos e serviços e lhe fornecer nossas últimas informações e notícias sobre o
SOC ou sobre a AGE;
para lhe permitir entrar em contato com a AGE para que possamos atendê-lo
(suporte); e
para realizar periodicamente determinadas pesquisas sobre o desempenho do SOC;

4. Divulgação de Dados Pessoais
Não divulgaremos seus Dados Pessoas, exceto conforme descrito nesta Política de
Privacidade.
A AGE está sempre aprimorando seus esforços para assegurar que esses Dados
Pessoais sejam respeitados segundo os níveis mais altos de regras de proteção de
dados, incluindo a LGPD e ISO 27.001.
Caso você opte por receber materiais promocionais, podemos notificá-lo
ocasionalmente sobre promoções especiais, novos produtos ou serviços ou outras
informações que possam interessá-lo.
Reservamos o nosso direito de divulgar Dados Pessoais nos casos em que for exigido
por lei aplicável ou proteger os direitos de propriedade ou segurança da AGE, de seus
colaboradores, de seus clientes ou público. Nestes casos, específicos, as informações e

dados poderão ser repassados às autoridades competentes, dando-se ciência ao Cliente
SOC, de modo que esta condição será utilizada pela AGE com total sigilo, quando esta
considerar apropriado ou necessário a manutenção da integridade e segurança de todos
os Clientes SOC e seus respectivos Usuários.

6. Cookies e outras tecnologias de rastreamento
O "cookie" é um arquivo que armazena temporariamente informações de texto sobre
sua navegação, este serve como troca de informações entre o servidor do site acessado
e o computador do usuário, aumentando a eficiência durante a navegação do usuário.
Algumas das nossas páginas da web utilizam "cookies" e outras tecnologias de
rastreamento. Algumas seções do site do SOC usam cookies para rastrear os padrões
de tráfego de usuários. Isso é feito para determinar a utilidade das informações do SOC
para nossos usuários e para ver se nossa estrutura de navegação é eficaz na hora de
ajudar os usuários a obter tais informações. A AGE não correlaciona essas informações
com Dados Pessoais a respeito de usuários individuais nem compartilha as informações
ou as vende para terceiros.
As tecnologias de rastreamento poderão registrar informações como domínio de
Internet e nomes de host, endereços de protocolo de Internet (IP), tipos de software de
navegador e sistema operacional, padrões de fluxo de cliques, datas e horários em que
nosso site é acessado. Nosso uso de cookies e de outras tecnologias de rastreamento
permite que melhoremos nosso site e sua experiência na web. Também poderemos
analisar informações que não contenham Informações Pessoais em busca de tendências
e estatísticas.

3. Segurança
a) Métodos de autenticação
Não há e não é prevista a criação de usuário padrão;
Além do nome do usuário e senha, também é necessário fornecer um ID de uso
pessoal e intransferível, para a autenticação no sistema;
A senha é criptografada utilizando o algoritmo Argon2;
A senha é armazenada criptografada e comparada da mesma maneira não sendo
possível a "descriptografia" pelo lado da aplicação;
Não é mantida nenhuma senha no código fonte da aplicação;
A mensagem de erro de autenticação é única para diferentes eventos (erro de
usuário, ID ou senha);
O aplicativo fornece métodos para recuperação de senha com envio ao e-mail do
próprio usuário solicitante, com o novo ID;
A senha se torna inativa após 30, 60 ou 90 dias sem a utilização ou após 3
tentativas falhas. Esse parâmetro é configurado pela empresa;
A aplicação pode ser configurada para oferecer a seguinte complexidade para
criação de senha;
As senhas devem ter pelo menos 8 caracteres entre letras e números;
A aplicação pode ser configurada para garantir que as senhas sejam alteradas pelo
menos a cada 30, 60 ou 90 dias, segundo o parâmetro da empresa, e o usuário
deve ter conhecimento da senha atual antes de realizar a alteração para uma nova
senha;
Apenas o administrador do sistema pode registrar um e-mail para um novo usuário
quando cria seu perfil ou alteração posterior. O usuário receberá um e-mail, em sua
própria conta, com a nova senha e ID;

O aplicativo armazena senhas criptografadas utilizando o algoritmo Argon2, dessa
forma, não é possível que ela seja de-criptografada;
Quando um novo usuário é criado, o administrador cria uma senha temporária para
que o usuário altere para uma nova senha no momento do primeiro acesso, a nova
é enviada para o e-mail do usuário.
b) WebServices (WS)
As requisições de WebServices são feitas utilizando o protocolo SOAP e são autenticadas,
além de usar criptografia em trânsito (TLS) para trazer mais segurança.
c) Ambiente de Teste/Homologação
Disponibilizamos de ambientes segregados do ambiente de produção para teste,
homologação e documentação da aplicação, adotando práticas de integração contínua
em nossos processos de desenvolvimento de software.
A aplicação tem como padrão publicação de novas funcionalidades quinzenalmente,
exceto em ocasiões extraordinárias. Correções de bugs são disponibilizadas conforme
descrito no contrato comercial. O processo de correção de bug é análogo ao de
desenvolvimento de novas funcionalidades, para amenizar problemas em ambiente de
produção.
Durante o teste da aplicação, o processo é realizado com usuário sem privilégios
administrativos (super usuário/usuário master), para garantir privilégio adequado ao
nível de acesso de cada usuário, exceto quando são testadas funções específicas do
perfil "Administrador" da aplicação.
d) Segurança de Rede
Os dados sensíveis de usuários trafegam criptografados, com o protocolo HTTPS.
A aplicação utiliza protocolo HTTPS (HTTP + TLS), sendo necessário permitir o acesso a
porta 443 para o funcionamento do SOC.
O Certificado HTTPS é emitido por Autoridade Certificadora reconhecida no mercado.
A aplicação dispõe de recurso que restringe acesso por IP, não permitindo acesso aos
usuários utilizando outro IP, que não previamente cadastrado no sistema, pelo
administrador do sistema.
A porta 80 é utilizada apenas para redirecionamento por meio de um serviço AWS. Não
permitindo nenhuma requisição chegar aos servidores.
e) Cross-Site Scripting (XSS)
Cross-Site Scripting (XSS) - Na codificação Java utilizamos filtros no momento da
exibição da página, que impedem que conteúdos de programas JavaScript sejam
interpretados, caso não sejam criados pela aplicação SOC.
f) Cross-Site Request Forgery (CSRF)
Cross-Site Request Forgery (CSRF) - A aplicação faz validação de sessão, não aceitando

requisições sem uma sessão válida, também não são aceitas requisições via GET.
g) Utilização de Componentes Vulneráveis Conhecidos
Possuímos políticas de segurança que definem o uso do componente e mantemos as
boas práticas de desenvolvimento de software, realizando testes de segurança, e
licenças confiáveis/aceitáveis.
h) Single Sign-On (SSO)
O Sistema SOC atua como um service provider (SP), no qual quando usuário solicitar
acesso e o mesmo esteja configurado para usar SSO SAML, direcionará o usuário para
a tela de autenticação do Identity Provider (IDP), o qual é o responsável por efetuar a
autenticação do usuário e redirecioná-lo para o Sistema SOC, que, de acordo com a
Assert devolvida pelo IDP concederá o acesso.
i) Web Application Firewall (WAF)
O Sistema SOC utiliza o serviço AWS WAF como firewall para aplicativos web que
permite monitorar as solicitações HTTP e HTTPS, além proteger contra exploits comuns
na web que podem afetar a disponibilidade, comprometer a segurança ou consumir
recursos em excesso.
O WAF fornece ao Sistema SOC um controle sobre as requisições realizadas, permitindo
criar regras de segurança que bloqueiam padrões de ataque comuns, como injeção de
SQL ou scripts entre sites, e regras que filtram padrões de tráfego específicos definidos.
j) IDS (Intrusion Detection System)
O Sistema SOC utiliza serviço AWS GuardDuty como IDS (Intrusion Detection System)
que analisa e processa feeds de inteligência contra ameaças, como listas de endereços
IP e domínios mal-intencionados. O serviço usa machine learning, detecção de
anomalias e inteligência integrada contra ameaças para identificar e priorizar possíveis
ameaças.
k) Cloudfront
Nosso sistema faz uso do Amazon CloudFront, serviço de distribuição de conteúdo da
AWS, para otimizar a performance e a disponibilidade da aplicação. Por meio de
servidores distribuídos globalmente, o CloudFront reduz a latência, melhora a
experiência do usuário e suporta automaticamente variações de demanda. Além do
ganho de desempenho, o CloudFront oferece camadas adicionais de segurança,
integrando-se a serviços como AWS Shield e AWS WAF, o que garante proteção contraataques de negação de serviço (DDoS) e vulnerabilidades em aplicações web.
l) Comunicação entre Microsserviços
Os microsserviços se comunicam através do protocolo SOAP ou utilizando filas. Para ser
permitida a comunicação, o serviço requisitante utiliza autenticação ao consumir outro
serviço.
O servidor de aplicação armazena as credenciais para autenticação no banco de dados
de forma segura utilizando criptografia e salt.

4. Utilização de Máquinas Virtuais - AWS EC2
Toda a operação do sistema SOC está hospedada na AWS, ou seja, utilizamos as
máquinas virtuais da AWS para o processamento dos Servidores de Aplicação WildFly
das aplicações SOC e MAESTRO. Por se tratar de uma estrutura elástica, não existe um
número fixo de servidores, as instâncias são criadas e destruídas On-Demand ,
conforme necessidade identificada pela equipe de monitoramento da AGE Technology.
Durante a execução das instâncias, elas se comportam como parte integrante do
Cluster de WildFly de maneira transparente para o sistema SOC e MAESTRO.
a) Serviço de mensagens utilizando Amazon Simple Email Service (SES)
O sistema SOC utiliza o serviço Amazon SES (Simple Email Service) que é um dos
muitos serviços da AWS (Amazon Web Services) para o envio de todos os e-mails do
sistema.
Um dos fatores que nos levaram a utilizar o Amazon SES é porque pode eliminar a
complexidade e o custo de construção de uma solução ou de licenciamento in-house de
e-mail, instalação e operação de um serviço de e-mail de terceiros. Outro fator
importante em qualquer esforço de envio de e-mail é a capacidade de entrega-a
porcentagem de seus e-mails que chegam em caixas de entrada dos destinatários. ISPs
usar filtros para detectar e-mails que parecem ser de spam (e-mails não solicitados,
indesejados) e impedir que essas mensagens sejam entregues. Mesmo que o seu email é legítimo, filtro de spam de um ISP poderia falsamente identificar seu e-mail
como spam, e colocá-lo na pasta de lixo eletrônico do destinatário ou bloqueá-lo
completamente.
O Amazon SES possui 2 formas para o envio de E-mail: SMTP e Amazon SES API.

O SOC utiliza a Amazon SES e envia e-mail usando o SMTP, o protocolo de e- mail mais
comum na Internet. O SOC pode enviar e-mail através da Amazon SES usando a
linguagem JAVA para se conectar à interface de SMTP nativo do Amazon SES. O
Amazon SES é divido em 3 servidores em diferentes continentes. Sendo 2 servidores
nos Estados Unidos e 1 servidor na Europa.
Buscando a alta disponibilidade e tolerância a falhas, nós utilizamos as 3 regiões

realizando um balanceamento de carga entre elas. Nossa cota de envio de e- mail por
dia é de 500.000 por servidor, totalizando 1.250.000 e-mails por dia, sendo que nos
dias de pico nossa utilização permanece abaixo de 10% de nossa capacidade.
Graças a estrutura provida pela Amazon SES, o sistema SOC recebe feedback de cada
mensagem enviada e implementa controles pró-ativos que impedem o envio de e-mail
seguidas vezes para e-mails inexistentes, além disso com o feedback da Amazon SES
conseguimos identificar possíveis e-mails que não foram recebidos por problemas no
provedor de e-mail do destinatário e disponibilizamos esse feedback para os usuários
responsáveis do SOC no cliente.
b) Serviço de armazenamento de arquivos utilizando Amazon S3.
O Sistema SOC possui o módulo Gestão Eletrônica de Documentos (GED) com a função
de gerenciar o armazenamento de arquivos de forma eletrônica, fechando o ciclo
completo, desde sua criação até o seu arquivamento, de maneira organizada, de modo
que a pesquisa por um item específico se torne mais fácil quando houver necessidade
no futuro.
O GED utiliza os serviços de Simple Storage Service (S3) da AWS para o
armazenamento dos arquivos. O S3 é um serviço de armazenamento de objetos na
AWS que oferece escalabilidade, disponibilidade de dados, segurança e performance.

5. Política de Backup
Descrição das políticas de backups, conforme Documento de Política de Backup e
Restore da AGE Technology.
a) Backup Completo
Todos os dias, as 23h40, é realizado 1(um) backup completo. Este backup é realizado
via snapshot fornecido pelo próprio serviço PaaS (Plataform as a Service) da AWS para
RDS (Amazon Relational Database Service).
b) Política de Retenção
Os arquivos de backup completos diários são armazenados no período compreendido de
35 dias, mensais por 1 ano e os anuais por 2 anos.
c) Cópias de Segurança (Backup)
As cópias de segurança (backup) do banco de dados são executadas através do serviço

RDS da AWS, ficando disponibilizado em todas as zonas de disponibilidade (multi AZ)
na região onde o banco de dados está localizado.
d) Estratégia de redundância - Banco de Dados
O serviço de banco de dados do Sistema SOC tem alta disponibilidade utilizando o RDS
Aurora-Mysql que possui um armazenamento de banco de dados virtual que abrange
várias zonas de disponibilidade (Multi-AZ), em que cada zona de disponibilidade conta
com uma cópia dos dados do cluster de banco de dados.
No serviço de banco de dados do Sistema SOC há um servidor principal (escrita) e uma
réplica (leitura) que estão localizados na mesma região de São Paulo.
Nenhum dos servidores de banco de dados tem conexão direta à internet.
e) Revisão de cópias de segurança realizadas
É revisada a atividade de backups diariamente, a equipe de operação verifica as
informações essenciais para manter a integridade dos arquivos gerados.
Como forma de aumentar a eficiência dos backups,mensalmente é restaurado um
backup do banco de dados em ambiente específico além da restauração é realizada a
atividade de subir uma versão da aplicação SOC, compatível com as estruturas
restauradas afim de aferir se os dados estão coesos e íntegros. Este processo é
registrado no sistema interno da empresa.
f) Restauração de Dados Pontual (point-in-time)
O serviço da RDS da AWS oferece restauração point-in-time que consiste restaurar o
banco de dados em um momento específico. Logo é possível com as solicitações de
restauração de dados para atendimento de clientes, incluído público interno
(desenvolvimento, homologação, bugs) são submetidas à análise da equipe de
operação, juntamente ao líder da área, definindo os prazos de disponibilidade, as
pessoas que terão acessos, se os dados serão acessados pelo cliente ou não.
Após essa análise, é encaminhado um e-mail para a área de Operação, que é
responsável pela restauração dos dados. Um outro e-mail é enviado ao desenvolvedor,
com as credenciais para acesso aos dados. Para essa atividade é estimada uma
quantidade de horas para a realização, e também passado uma data em que os dados
estarão disponíveis para consulta.
Ainda com o fluxo desse processo é criado um registro em planilha que controla quem
está acessando esses dados e o período de vigência dos acessos. A planilha é revisada
semanalmente e, se possível, são revogados acessos caso os usuários já tenham
concluído as tarefas que necessitavam das informações.
g) Estratégia de Backup - Servidores
Utilizamos o recurso na AWS de Imagens de máquina da Amazon (AMIs) para criamos
backup de nossos servidores de aplicação.

6. Registro de Eventos - LOGS
A aplicação registra eventos como acesso realizado, alterações de dados na maioria das
telas, podendo ser consultado pelo administrador da aplicação.

7. Redundância
Em caso de falha do software no servidor de aplicação Wildfly, temos um ambiente na
AWS com diversas instâncias de Wildfly. Nestas circunstâncias, as requisições serão
automaticamente enviadas para outro servidor de forma transparente.
Para problemas relacionados a aplicação, o Sistema SOC dispõe de um cluster para
atendimento de requisições de click de tela dos clientes composto por Apache e Wildfly
em cada servidor, em casos de falha de um servidor (hardware ou aplicação), as
requisições serão redirecionadas automaticamente para outro servidor do cluster.
Para problemas relacionados ao banco de dados, o Sistema SOC dispõe de um cluster
de armazenamento de banco de dado em 1 região com 3 zonas de disponibilidade que
mantem os mesmos dados (sincronizados). Em casos de problemas/falha do
armazenamento dos dados e/ou da instância de banco de dados ocorrerá o failover
automaticamente para outra instância em outra zona de disponibilidade.

8. Arquitetura
O sistema SOC é uma aplicação que utiliza internet e navegadores para o seu
funcionamento, esse modelo de estrutura é chamado SaaS, Software como um Serviço,
termo traduzido do inglês Software as a Service (SaaS), os sites que utilizam a
Computação em Nuvem para oferecer serviços online, sem a necessidade de instalar
programas no computador. Como os dados podem ser acessados via web, os SaaS
dispensam compras com diversas licenças para máquinas diferentes e podem ser
acessados com diversos dispositivos, como computadores, notebooks, tablets ou
smartphones.
a) Detalhes da infraestrutura da Aplicação SOC
Banco de Dados: RDS (Relational Database Service) AURORA-MYSQL
Linguagem de Programação: Java
Sistema Operacional: Amazon Linux
Servidor Web: Apache Web Server
Servidor de Aplicação: Wildfly
b) Função como serviço (AWS Lambda)
O AWS Lambda é um serviço de computação sem servidor que permite executar código

sem provisionar ou gerenciar servidores.
Com o Lambda, podemos executar o código para praticamente qualquer tipo de
aplicação ou serviço de back-end, tudo sem precisar de administração. Basta fazer o
upload do código como um arquivo ZIP ou imagem de contêiner, e o Lambda aloca de
maneira automática e precisa o poder de execução de computação e executa com base
na solicitação ou evento de entrada, para qualquer dimensão de tráfego.
c) Api Gateway
O Amazon API Gateway é um serviço gerenciado que facilita criação, modificação,
monitoração e proteção das APIs em qualquer escala com facilidade. APIs agem como a
porta de entrada para aplicativos acessarem dados, lógica de negócios ou
funcionalidade dos serviços de back-end.
O API Gateway administra todas as tarefas envolvidas no recebimento e processamento
de até centenas de milhares de chamadas de API simultâneas, inclusive gerenciamento
de tráfego, suporte de CORS, controle de autorização e acesso, com fluxo controlado,
monitoramento e gerenciamento de versões de API.
d) Fila (AWS simple queue service ou AWS SQS)
O Amazon Simple Queue Service (SQS) é um serviço de filas de mensagens gerenciado
que permite o desacoplamento e a escalabilidade de microsserviços, sistemas
distribuídos e aplicativos sem servidor. O SQS elimina a complexidade e a sobrecarga
associadas ao gerenciamento e à operação de middleware orientado a mensagens,
além de permitir que os desenvolvedores se dediquem a criar diferenciais. O SQS pode
ser usado para enviar, armazenar e receber mensagens entre componentes de software
em qualquer volume, sem perder mensagens ou precisar que outros serviços estejam
disponíveis.
e) AWS Chime
O Amazon Chime é um aplicativo na nuvem que permite que você estabeleça contato
on-line entre pessoas. Com o Amazon Chime, podemos realizar reuniões on-line e
videoconferências.
f) AWS ElasticSearch
O Amazon Elasticsearch Service é um serviço totalmente gerenciado que facilita a
implantação, a segurança e a execução do Elasticsearch de forma eficaz e em grande
escala. Ele possui uma estrutura para monitorar a ferramenta e seu desempenho. O
serviço fornece suporte para APIs ElasticSearch de software livre, Kibana gerenciado,
integração com Logstash e outros serviços da AWS, alertas e consultas SQL internos.
g) AWS ElastiCache
Com o Amazon ElastiCache é um serviço gerenciado de conhecidos repositórios de
dados na memória compatíveis com código aberto na nuvem (redis e memcache).
Devido ao cache ser feito em memória, é bastante utilizada como cache ou banco de
dados para sessão pois tem maior desempenho.

h) VPC / Subnets
A infraestrutura do SOC é dividida em basicamente 3 subredes. A característica que as
diferencia são: concessão de acesso a internet através de um ponto centralizado,
permissão de acesso diretamente na internet e restrição de acesso a internet. Os
servidores que precisam de acesso externo, são colocados em uma das redes que
possibilita tal acesso. Todas as máquinas têm políticas de restrição que mesmo com
acesso a internet, limitam e impedem acesso externo ao servidor.
i) Arquivos hospedados e/ou disponíveis
Os arquivos enviados por empresas que são hospedados no SOC em seu acesso
limitado a empresa e somente por protocolocos http.
Os arquivos ged são validados com antivirus, prevenindo armazenamento de possíveis
ameaças.

a) Software de Monitoramento - New Relic
O sistema SOC utiliza o New Relic para o monitoramento da Aplicação e servidores que
a hospedam.

O principal propósito do New Relic é auxiliar no diagnóstico de possíveis problemas no
código da aplicação, facilitando a identificação de gargalos que prejudiquem sua
performance.
A partir de gráficos de desempenho de fácil compreensão, é possível acompanhar

conexões com serviços externos, visualizar relatórios de disponibilidade e de erros
recorrentes, configurar alertas, entre outros.
O New Relic permite a configuração de alertas por e-mail através de métricas definidas
através de configuração parametrizada permitindo aos administradores do ambiente
uma administração mais segura e com maior visibilidade de cada métrica estabelecida.
Com o New Relic o SOC realiza em tempo real o monitoramento da aplicação e dos
servidores, destacando:

Desempenho do navegador em tempo real, com informações detalhadas da

páginas para o usuário final;
Velocidade de renderização JavaScript;
Latência de rede.
Rastreamento de Transação
Obter detalhes completos de rastreamento em nível de código;
Consultas SQL dentro da faixa transações específicas;
Rastreamento entre aplicações para transações distribuídas Performance do SQL
Acompanhamento das transações de banco de dados mais lentos até o nível de
SQL;
Tendências de uso e de desempenho ao longo do tempo.
Monitorização de Servidores
Utilização de CPU;
Utilização de memória;
Utilização de Rede;
Processos em execução.

b) Software de Monitoramento - Amazon CloudWatch
Utilizamos o serviço de Amazon CloudWatch que monitora nossos recursos da AWS em
tempo real. Esta ferramenta é utilizada para coletar e monitorar métricas, que são as
variáveis para medir e avaliar os recursos e aplicativos. Utilizam alarmes que observem
métricas e enviem notificações ou façam alterações automaticamente, de forma
transparente para o Sistema SOC, nos recursos que está sendo monitorado quando um
limite é violado, serviço conhecido como auto scaling.

10. Controle de Acesso para Manutenção da Infraestrutura - AWS Control
Tower
AWS Control Tower é uma ferramenta de governança de multiconta que permitiu
simplicidade e segurança gerenciar as várias contas na AWS para as atividades no
Sistema SOC, desde desenvolvimento até a correção de bugs, dentre elas segregação
de funções entre os colaboradores e rastreabilidade, tornando-se mais seguro e
permeável com as práticas recomendadas e estabelecidas.
O AWS Control Tower oferece uma maneira simples de configurar e controlar um
ambiente de várias contas da AWS. Para facilitar este gerenciamento utiliza-se de
serviços como AWS Organizations, AWS Service Catalog e AWS Single Sign-on. O
Control Tower segue as melhores práticas e aplica controles preventivos e de detetive
(guardrails) como por exemplo garantir que os logs de segurança e as permissões
necessárias de acesso entre contas sejam criados e não alterados.
