1.

Introdução

1.1

Objetivo
Este Web Service permite a inclusão de solicitação de processamento da funcionalidade
“Processamento Assíncrono”. Para mais detalhes sobre a funcionalidade, pode ser consultado o
tópico “Processamento Assíncrono”, disponível no Manual.

1.2

Funcionamento
1. As propriedades a serem enviadas para o SOC são populadas no Web Service com os
dados de um tipo de processamento existente, o qual será realizada a solicitação de
processamento;
2. Após o serviço ser consumido, o SOC emite uma mensagem de retorno informando o
ocorrido com a requisição.
3. O WebService foi projetado para incluir uma solicitação de processamento por vez que é
invocado.

1.3

Considerações
1. O desenvolvimento da lógica para a chamada ao WebService é de responsabilidade do
cliente;
2. O arquivo WSDL a ser usado já será enviado com as configurações de acordo com o
ambiente que for definido com o cliente.
3. O acesso ao serviço deve constar nas configurações de integração do usuário.
4. A solicitação de processamento deve ser referente a um tipo de processamento existente
e válido. Os parâmetros devem ser informados de acordo com o tipo desejado.
5. O certificado de conexão HTTPS disponibilizado no WebService é renovado anualmente,
de forma automática e antecipadamente à data de expiração.

segurança fornecidas pela especificação WS-Security, utilizando a TAG Header com itens de
segurança conforme política. Segue um modelo do que deverá ser informado.

2.3

Considerações para as Propriedades da tag wsse security
Propriedade

Timestamp

Detalhes
É o tempo de validade da requisição.
Recomendamos o uso de um minuto. Requisições
com timestamp superior a dois minutos serão
negadas.

Username

Código do usuário no sistema SOC precedido
obrigatoriamente pela letra U (disponível nas
configurações de integração).

Password

Chave de acesso do usuário (disponível nas
configurações de integração). Contudo o cliente
deverá informar o mesmo com o Tipo
“PasswordDigest”

Nonce

É um valor randômico que o cliente do serviço
deverá criar para cada requisição que enviar.

Signature

Deve ser assinado com o certificado que a AGE
fornecerá.

EncryptedKey

Deve ser criptografado com o certificado que a
AGE fornecerá.

5.1.3

Requisição expirada

<soap:Envelope xmlns:soap="http://schemas.xmlsoap.org/soap/envelope/">
<SOAP-ENV:Header xmlns:SOAP-ENV="http://schemas.xmlsoap.org/soap/envelope/"/>
<soap:Body>
<soap:Fault>
<faultcode xmlns:ns1="http://docs.oasis-open.org/wss/2004/01/oasis200401-wss-wssecurity-secext-1.0.xsd">ns1:MessageExpired</faultcode>
<faultstring>The message has expired</faultstring>
</soap:Fault>
</soap:Body>
</soap:Envelope>

A falha acima ocorre quando o elemento de segurança “timestamp” é violado. O timestamp
verifica a validade da mensagem enviada em termos de tempo.
O sender especifica o tempo de validade, então, dois elementos são definidos no momento em
que a mensagem é enviada:
Onde:

<wsu:Created>2014-06-18T20:20:44.623Z</wsu:Created>

wsu:Created = hora atual;

<wsu:Expires>2014-06-18T20:21:44.623Z</wsu:Expires>

wsu:Expires = wsu:Created + (tempo de validade);
