Especificação Técnica
1.

Introdução

1.1

Objetivo
Permitir ao cliente a possibilidade de criar, alterar, consultar e excluir cargos, a partir do consumo
de WebService.

1.2

Funcionamento
1. As propriedades a serem enviadas para o SOC são populadas no WebService com os dados do
cargo que será manipulado pelo cliente a partir de sua origem.
2. Após o serviço ser consumido, o SOC emite uma mensagem de retorno informando os dados do
cargo manipulado, bem como possíveis irregularidades nos dados enviados.

1.3

Considerações
1. O desenvolvimento da lógica para a chamada ao WebService é de responsabilidade do cliente;
2. O WebService foi projetado para atualizar/incluir/excluir um cargo por vez que é invocado, exceto
a porta de consulta, que devolve uma lista de cargos;
3. O arquivo WSDL a ser usado será enviado com as configurações de acordo com o ambiente que
for definido com o cliente.
4. O acesso ao serviço deve constar nas configurações de integração do usuário.
5. Propriedades não enviadas serão desconsideradas, se enviada em branco será considerado.
6. O certificado de conexão HTTPS disponibilizado no WebService é renovado anualmente, de forma
automática e antecipadamente à data de expiração.
7. O Webservice não oferece suporte ao paralelismo de requisições. As requisições devem ser
enviadas de forma sequencial. Em caso de identificação de paralelismo que prejudique a
performance do SOC, a integração será desligada sem aviso prévio.

Considerações para as Propriedades da tag wsse security

2.3

Propriedade
Timestamp

Detalhes
É o tempo de validade da requisição. Recomendamos o uso de um minuto.
Requisições com timestamp superior a dois minutos serão negadas.

Username

Código do usuário no sistema SOC precedido obrigatoriamente pela letra U
(disponível nas configurações de integração).

Password

Chave de acesso do usuário (disponível nas configurações de integração).
Contudo o cliente deverá informar o mesmo com o Tipo “PasswordDigest”

Nonce

É um valor randômico que o cliente do serviço deverá criar para cada
requisição que enviar.

Signature

Tag responsável pela integridade dos dados trafegados em uma requisição.

EncryptedKey

Tag responsável por manter os dados seguro enquanto são trafegados.

2.4

Configurações adicionais para a tag wsse security
Para melhorar ainda mais a segurança dos WebServices, A AGE Desenvolvimento LTDA,

disponibiliza a opção de criptografia e assinatura digital nos WebServices. Quando utilizado a url da
versão com segurança deverá ser adicionado as tags Signature e EncryptedKey no header da requisição.
A AGE fornecerá um keystore contendo dois alias. Para a assinatura digital (Signature) utilizar o
alias clientkey e para a criptografia (EncryptedKey) utilizar o alias serverkey.
O webservice com segurança adicional é utilizado em uma URL diferente da convencional. O
endereço consta no WSDL do serviço.

3.1.3

Considerações para as propriedades


O campo “codigo” é obrigatório apenas na alteração. O campo deve ser informado de
acordo com o valor definido no campo tipoBusca. Quando o tipoBusca for CODIGO, deve
receber o Código SOC do cargo. Quando o tipoBusca for CODIGO_RH, deve receber o
Código RH do cargo.



O campo “nome” é obrigatório apenas na inclusão.



Na alteração e na consulta, quando o tipoBusca selecionado for CODIGO_RH, é
obrigatória a busca pelo campo CODIGO para informar o código RH do cargo.



Na inclusão de cargo, quando não informado um código ou quando informado o valor 0,
será realizada a geração automática do código do cargo. O valor inicial para geração do
código pode ser configurado nos parâmetros gerais da empresa.



Quando o parâmetro “Obriga campos específicos deste leiaute?” do layout S-2240 nos
parâmetros eSocial da empresa estiver habilitado, o campo será limitado a 999
caracteres.

pelo campo CODIGO para informar o código RH do cargo.

Na inclusão de cargo, quando não informado um código ou quando informado o valor 0,
será realizada a geração automática do código do cargo. O valor inicial para geração do
código pode ser configurado nos parâmetros gerais da empresa.

Quando o parâmetro “Obriga campos específicos deste leiaute?” do layout S-2240 nos
parâmetros eSocial da empresa estiver habilitado, o campo será limitado a 999
caracteres.

Falhas nas ações Inserir/Alterar
Ao inserir/alterar um cargo, caso os dados não estejam de acordo, poderá ocorrer as seguintes
falhas:


Existe um cargo com o nome informado: Mensagem retornada quando está se
tentando gravar (incluir ou alterar) o cadastro de um cargo com o mesmo nome de um
cargo já existente na empresa informada.



Existe um cargo com o código RH informado: Mensagem retornada quando está se
tentando gravar (incluir ou alterar) o cadastro de um cargo com o mesmo Código RH de
um cargo já existente na empresa informada.



Código do cargo inválido: Mensagem retornada quando o valor informado na
propriedade codigo não é um código de cargo válido.



Código RH do Cargo é obrigatório.: Mensagem retornada na inclusão quando o
campo codigoRh não é informado na requisição e o parâmetro geral "Obriga preencher
Código do RH do Cargo" está habilitado na empresa da requisição. Na alteração a
mensagem irá retornar quando o campo codigoRh não for informado na requisição, o
parâmetro estiver habilitado na empresa e o cargo informado na requisição não tem
Código do Rh preenchido no SOC.



CargoWsVo.funcao não tem entre 0 e 200 caracteres: Mensagem retornada
quando o valor enviado no campo “funcao” ultrapassa o tamanho máximo permitido de
200 caracteres.

Falhas na ação de Excluir
Ao tentar efetuar a exclusão de um cargo poderão ocorrer as seguintes falhas:


Existe funcionário com histórico nesse cargo: Mensagem retornada quando o cargo
o qual está sendo realizada a tentativa de exclusão consta no histórico de ao menos um
funcionário da empresa informada, impedindo a exclusão.



Existe um GHE aplicado para este cargo: Mensagem retornada quando o cargo o
qual está sendo realizada a tentativa de exclusão possui ao menos um GHE aplicado,
impedindo a exclusão.



Cargo sendo Usado: Mensagem retornada quando o cargo o qual está sendo realizada
a tentativa de exclusão está sendo utilizado na empresa informada, impedindo a
exclusão.
