1.

Introdução

1.1

Objetivo
Serviço que permite o upload de arquivo no GED.

1.2

Funcionamento
1. As propriedades a serem enviadas para o SOC são populadas no WebService com os
dados do arquivo.
2. Após o serviço ser consumido, o SOC emite uma mensagem de retorno informando se o
arquivo foi gravado.

1.3

Considerações
1. O desenvolvimento da lógica para a chamada ao WebService é de responsabilidade do
cliente;
2. O WebService foi projetado para receber um arquivo por vez que é invocado;
3. O arquivo WSDL a ser usado já será enviado com as configurações de acordo com o
ambiente que for definido com o cliente;
4. O arquivo devera ser enviado em anexo utilizando MTOM-XOP, quando for uma
requisição sem criptografia;
5. O usuário informado deverá ter os acessos a SOCGED e UPLOAD DE ARQUIVOS, caso
não exista um tipo de GED cadastrado da classificação informada na requisição, o mesmo
deverá ter acesso a incluir “Tipo de SOCGED” ou se existir, o usuário devera ter acesso
ao tipo já cadastrado.
6. O acesso ao serviço deve constar nas configurações de integração do usuário.
7. O certificado de conexão HTTPS disponibilizado no WebService é renovado anualmente,
de forma automática e antecipadamente à data de expiração.

Configurações adicionais para a tag wsse security
Para melhorar ainda mais a segurança dos WebServices, A AGE Desenvolvimento LTDA,

disponibiliza a opção de criptografia e assinatura digital nos WebServices. Quando utilizado a url da
versão com segurança deverá ser adicionado as tags Signature e EncryptedKey no header da requisição.
A AGE fornecerá um keystore contendo dois alias. Para a assinatura digital (Signature) utilizar o
alias clientkey e para a criptografia (EncryptedKey) utilizar o alias serverkey.
O webservice com segurança adicional é utilizado em uma URL diferente da convencional. O
endereço consta no WSDL do serviço.

5.1.3

Requisição expirada
<soap:Envelope xmlns:soap="http://schemas.xmlsoap.org/soap/envelope/">
<SOAP-ENV:Header xmlns:SOAP-ENV="http://schemas.xmlsoap.org/soap/envelope/"/>
<soap:Body>
<soap:Fault>
<faultcode xmlns:ns1="http://docs.oasis-open.org/wss/2004/01/oasis200401-wss-wssecurity-secext-1.0.xsd">ns1:MessageExpired</faultcode>
<faultstring>The message has expired</faultstring>
</soap:Fault>
</soap:Body>
</soap:Envelope>
A falha acima ocorre quando o elemento de segurança “timestamp” é violado. O timestamp
verifica a validade da mensagem enviada em termos de tempo.
O sender especifica o tempo de validade, então, dois elementos são definidos no momento em
que a mensagem é enviada:
Onde:

<wsu:Created>2014-06-18T20:20:44.623Z</wsu:Created>

wsu:Created = hora atual;

<wsu:Expires>2014-06-18T20:21:44.623Z</wsu:Expires>

Falhas de Acesso
A tag Identificação, caso o preenchimento não esteja de acordo, poderá prover as seguintes
falhas:


Identificação Inválida: Mensagem retornada quando os dados informados na tag
identificacaoWsVo não configuram uma credencial válida de acesso aos Web Services



Empresa Invalida: Mensagem retornada quando a empresa informada não é valida
para a identificação enviada na requisição.



Usuário Sem Acesso: Mensagem retornada quando o usuário não possui os acessos
necessários para a ação solicitada. Os acessos necessários estão descritos no cadastro do
Web Service.



Login não Localizado: Mensagem retornada quando não é possível localizar o usuário
informado na requisição.

5.3

Campos Obrigatórios não preenchidos
Quando campos obrigatórios não são preenchidos, o serviço lança uma falha, notificando o
campo que deveria ter sido informado.
Ex: uma requisição que não informa o arquivo que está sendo feito o upload o serviço retornará
a seguinte response:

<soap:Envelope xmlns:soap="http://schemas.xmlsoap.org/soap/envelope/">
<soap:Body>
<soap:Fault>
<faultcode>soap:Server</faultcode>
<faultstring>Anexo não enviado ou Inválido, deve ser usado anexo MTOMXOP</faultstring>
</soap:Fault>

5.4

Falhas no preenchimento da mensagem
 O campo observacao deve possuir entre 0 e 3400 caracteres.: Mensagem retornada
quando o campo observacao informado excede 3400 caracteres.
 Tamanho Do arquivo Maior que o permitido, tamanho maximo permitido –
10485760: Mensagem retornada quando o tamanho do arquivo enviado é superior a 10
Megabytes.
 Anexo nao enviado ou Invalido, deve ser usado anexo MTOM-XOP: Mensagem
retornada quando a requisição é enviada sem arquivo em anexo ou quando não é utilizado o
content-type “application/xop+xml”.
 O campo com.age.soc.vo.services.UploadArquivosWsVo.codigoSequencialFicha não
pode ser vazio!: Mensagem retornada quando o campo codigoSequencialFicha é enviado vazio
ou com um valor inválido. Verificar referência 6 desta documentação técnica.
 É necessario preencher o campo nomeGed ou codigoGed: Mensagem retornada quando é
enviada a classificação GED e não são informados os campos: nomeGed ou codigoGed.
 É necessario preencher o campo nomeGed para criar um ged: Mensagem retornada
quando o nomeGed não é enviado, a classificação GED está sendo utilizada e, o codigoGed
informado não existe.
 É necessario preencher o campo nomeTipoGed ou codigoTipoGed: Mensagem retornada
quando não são enviados os campos nomeTipoGed ou codigoTipoGed para criar o SOCGED.
